核心页 1 动态采样机制 — Agentic Adaptive Evaluation

一句话：DGM 用固定子集（10→60→200）评每个新版本；我们改成 为每一次改动，动态挑最能暴露它收益 / 回归的任务，再用 parent/child 配对决策这次改动是保留还是回退。

输入

  • 冻结任务目录：DGM 200 道 SWE-bench Verified（hash 锚定，153 Django / 25 Sphinx / 22 Astropy）
  • TaskCard（问题文本 + BM25 词项 + 1024-D 向量）
  • CandidateChangeCard：父→子 diff、改动路径 / 符号
  • BadCaseCard：父代失败案例
  • 隔离：selector 看不到 gold patch / test patch / 私有评测日志 / D_test

输出

  • 一个冻结的任务集（selector 选中 + 独立 audit）
  • 每个任务带 retrieval_role + 自然语言 rationale
  • parent/child 在该集上的配对执行结果
  • 三态决策：ACCEPT / ROLLBACK / ESCALATE（+ fail-closed 的 INVALID）
  • 附带 Coverage / Redundancy 审计报告

核心页 1 · 关键 公式对应什么？LLM 不是看分数做决定

设计原则（文档原文）："The model may propose what to inspect. Immutable execution evidence decides." LLM 做检索规划 + 假设生成；公式是围绕它的确定性仲裁器 + 报告器。
① LLM Selector（冻结）
自己写 query、自己选调哪个工具（search_lexical/search_semantic）、 调几次、何时停 → 输出带角色+理由的任务集。 不吐标量分、不做裁决。
→
② 确定性仲裁（非 LLM）
repair/regression 假设按角色字典序优先； 竞争容量时按 ΔCoverage 挑； 多样性用贪心补；追加 LLM 看不到的 audit。
→
③ 确定性决策引擎（非 LLM）
配对执行后，用 bootstrap + McNemar 出 ACCEPT/ROLLBACK/ESCALATE。 全程不调 LLM。

每条公式归谁、干什么

公式谁算agentic 角色
BM25 / cosine代码工具内部算法；LLM 调检索后给返回候选排序（不负责选工具）
ΔCoverage(x｜S)代码①LLM 可只读调用辅助推理
②代码仲裁 / 填多样性
Coverage / Redundancy代码冻结后只报告 / 审计
delta / bootstrap / McNemar代码最终三态裁决
方向：LLM 驱动"写 query / 选工具 / 查几次 / 何时停"（agentic）；BM25·cosine 只是工具内部给候选排序，不参与选工具。

为什么不用一个加权总分？

  • 不做 a·repair + b·regression + c·diversity
  • 四个检索角色量纲不可比，加权会引入脆弱、无依据的系数
  • 改用字典序 + 边际覆盖填充：可解释、可消融
  • LLM 唯一能主动碰的公式是把 marginal_coverage 当只读工具查，仍只吐"带理由的集合"

核心页 1 · 补充 两梯队选择 · 停机条件 · 评估对象

梯队 1 · LLM 直接假设（agentic 主力）
LLM 提议 repair_cause + regression 任务，每个须带 evidence_reference（必须指向它检索过的结果，不能凭空提）。 正常情况（提议数 ≤ 容量）全部保留。 ΔCoverage 在这梯队不做筛选，只：①超容量时取舍 ②零增益重复须写 necessary_distinct_reason，否则 fail-closed。
→
梯队 2 · ΔCoverage 贪心补位（确定性）
仅当梯队 1 没填满 target 才触发。候选池 = LLM inspected 子集； 池空才回退全集 U。每步选边际覆盖最大者，零增益候选直接拒。 这步可消融（见右下）。

inspected 候选池怎么构造

  • 任务进池 ⟺ 出现在 LLM 检索结果：search_lexical/search_semantic 命中、get_task(id)、marginal_coverage 参数
  • get_bad_case/get_change/inspect_round_results 不进池
  • 纯 LLM 驱动：LLM 搜什么，池里就有什么
  • 池同时限定「LLM 能提什么」+「补位候选来源」

停机条件（≠ ΔCoverage 饱和）

  • task_budget 用尽
  • LLM finish_round，理由须以 evidence_saturation: 开头
  • max_rounds / selector_token_budget / selector_time_limit 任一触顶

评估对象是「一次改动」，不是某个 task

  • 统计单位 = 一条边 P → C（parent vs child 两版本）
  • 初始已选集 S = ∅；种子 = CandidateChangeCard(diff) + BadCaseCard
  • 没有"当前正在做的 task"这回事
  • U = 冻结候选全集：当前 200 / 协议本意 D_evolve=60
消融直觉成立：设计文档 §10 已预注册"去掉 facility-location 补位"。 去掉后 LLM 少提时 batch 变小，风险是可能塌缩到近重复 trace / 漏覆盖——值得实测。

核心页 2 动态回退机制 — Repair-First CLM

一句话：DGM 没有"回退"这个动作（archive 只增、按分数重选 parent）。我们把进化史建成 可回放的 patch 谱系，用可执行反事实 replay 直接定位"一最小充分移除集"，退到最早移除点之前，再重放不依赖它的后续有效改动。

输入 / 输出

  • 入：线性 lineage（每 patch 一节点，带 changedFiles / dependsOn）
  • 入：FailureBundle（失败摘要、candidate slice、LLM 软先验 priorOrder、sliceAuditRecall）
  • 入：probe() — 给定 active patch 集合 → 是否复现失败（可执行验证，奇数次多数票去噪）
  • 出：removedPatchIds（最小充分移除集）+ RollbackPlan
  • 出：method ∈ {singleton / sliced-ddmin / full-ddmin / abstain}
  • apply 默认 dry-run，必须用户确认，严禁动 git 历史

三因子 + 硬门控

  • A 候选先验：LLM 只排序 / 缩小候选，不硬删
  • B 反事实验证：先验 singleton 移除 → 不够才对移除集跑 ddmin
  • C rollback-and-replay：落点=最早移除 patch 的父节点；后续 patch 按依赖拓扑重放
  • 成本门控：slice ≤ 30% 且 recall ≥ 95% 才用 sliced ddmin，否则退回 full ddmin
结果：Repair-First 比旧 failure-first 减少 42.86%–49.89% probes； clean repair=1.000，5%/10% 噪声 repair=0.973/0.970（均在 2-point non-inferiority margin 内）。

附录 A 动态采样公式 + notation 图例

相似度（语义检索的基础量）

sim(i, j) = max(0, cosine(emb(i), emb(j)))
notation ✓ 全部符号已解释
i, j
两个任务（TaskCard）
emb(·)
任务的 L2 归一化 1024-D Qwen3 向量
cosine(a,b)
归一化向量点积 = 余弦相似度
max(0,·)
负值截断为 0，使 sim ∈ [0,1]

覆盖度（facility-location，衡量代表性）

Coverage(S) = (1/|U|) · Σu∈U maxs∈S sim(u, s)
notation ✓
S
已选中的任务集合
U
universe：冻结的可选任务全集
|U|
U 中任务数量
u
universe 中的一个任务
s
S 中的一个任务
maxs∈S sim(u,s)
u 在 S 中最像的"代表"

边际覆盖（加入 x 的增益，仲裁用）

ΔCoverage(x | S) = (1/|U|) · Σu∈U max(0, sim(u,x) − maxs∈S sim(u,s))
notation ✓
x
一个尚未被选中的候选任务
x | S
"在已选 S 的条件下" x 的增量
max(0,·)
只计正增益（diminishing returns）

冗余度（只报告，不进决策）

Redundancy(S) = (1/|S|) · Σs∈S maxt∈S, t≠s sim(s, t)
notation ✓
t
S 中另一个任务（≠ s）
|S|
已选集合大小；<2 时定义为 0
近 1 = 多数任务有近似邻居（塌缩）；低 = 分布开。冗余不从任何 LLM 分里扣，只暴露"选择塌缩"。

词法检索 BM25（lexical 候选排序）

score(q,d) = Σw∈q IDF(w) · f(w,d)·(k₁+1) ──────────────────── f(w,d) + k₁·(1 − b + b·|d|/avgdl) IDF(w) = log(1 + (N − df(w) + 0.5)/(df(w) + 0.5))
notation ✓ 全部符号已解释
q, d
查询 / 文档（任务卡文本）
w
查询中的一个词项（term）
f(w,d)
词 w 在文档 d 中的频次
|d|
文档 d 的词长
avgdl
语料平均文档长度
N
文档总数（=200）
df(w)
含词 w 的文档数
k₁, b
BM25 参数（代码取 k₁=1.2, b=0.75）
词法与语义是两路分开的结果流，不混成一个加权分；LLM 自己看两路再决定要不要再查。

配对差值与三态决策（确定性）

δ(task) = Y(child,task) − Y(parent,task) ∈ {−1,0,1} Δ̄ = meantask δ(task) # 配对均值 [L, U*] = paired-bootstrap 95% CI of Δ̄ ACCEPT : L > acceptance_margin 且 audit 通过 ROLLBACK : U* ≤ rollback_margin ESCALATE : 其余（或 targeted 与 audit 矛盾）
notation ✓
Y(v,task)
版本 v 是否解出该任务 ∈ {0,1}
δ(task)
child 减 parent 的单任务差
Δ̄
所有配对任务差的均值
L, U*
bootstrap 置信区间的下 / 上界
audit 通过
audit 任务上均值 ≥ audit_guard_min_delta
McNemar
只在 discordant 对（parent-only+child-only）上做精确检验
margin / 置信水平 / bootstrap 种子都是预注册的策略值，代码里没有魔法阈值。

附录 C 动态回退公式：ddmin / 门控 / 成本 + notation

probe 去噪 + 修复判据

probe(P).failed = ( votes > repeats / 2 ) # 多数票 repairs(R) = ¬ probe( allPatches ∖ R ).failed
notation ✓
P
一组 active patch id
votes
多次重复里判定"失败"的次数
repeats
probe 重复次数（奇数）
R
候选"移除集"
allPatches ∖ R
全集去掉 R 后仍激活的 patch
repairs(R)
移除 R 后失败是否消失

sliced ddmin 硬门控

sliceFraction = |candidates| / |allPatches| 启用 sliced ⟺ sliceFraction ≤ 0.30 且 sliceAuditRecall ≥ 0.95 否则 → full ddmin（准确优先）
notation ✓
candidates
先验给出的候选 patch 子集
sliceAuditRecall
历史审计里 slice 覆盖真因的召回率

ddmin（最小充分移除集）

  • granularity 从 2 起，试子块 / 补集能否仍 repairs()
  • 能则缩小搜索空间，逐步细化到最小集合
  • 先走先验 singleton 快路径；不行再整体 ddmin

RollbackPlan 的重放跳过规则

rollbackCkpt = parent(最早被移除的 patch) replay 跳过 patch 的 3 种原因： · causal （本身在移除集里） · dependency （dependsOn 了被移除项） · overlapping-files（改了与移除项相同文件）

成本模型（第 3 条 claim）

C_total = M × c_node
notation ✓
C_total
到达目标分数的总评测成本
M
被评测的节点数
c_node
每节点评测成本
杠杆2（主）

partial 复评 → 降 c_node，仅局部改动有效

主动声明的边界（讲出来是加分）

  • P2 的 69.5% 用了一轮隐藏官方 evaluator 反馈，是"恢复上界(recovery upper bound)"，不是标准单次提交 SWE-bench 分数
  • 不能据此宣称打赢 DGM 或原版 Pi
  • P1=原版 Pi 单提交才是严格可比基线（50.0%）
  • 动态采样当前实现仍把 200 全集暴露给 selector，60/140 隔离是待做的实现门
  • A3 多代回退仍需 Phase-2 release gate 才能作为 headline

时间与规模（防"两周"误解）

  • 18.23 天日历跨度里 16.99 天是显式暂停（用户暂停 / Docker 恢复 / 依赖修复 / 凭据恢复）
  • 协议记录活跃墙钟 29.89 小时
  • 直接执行 13.57 小时（P1 8.75h + P2 增量 4.82h）
  • "两周"是 DGM 论文开放式进化描述，非可比时间基线
