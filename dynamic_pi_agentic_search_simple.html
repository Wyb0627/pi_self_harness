动态采样机制 · 精简版（agentic search 视角）

一句话:动态采样 = 以"一次 harness 改动"
为 query 的 Agentic Search

输入一次改动的证据(diff + 历史失败)→ LLM 用检索工具自主搜任务 → 直接提出一批任务 → 让 parent vs child 在这批任务上配对跑 → 确定性裁决:保留 / 回退 / 升级。
主干:LLM 检索 + 提议
量尺用途:配对测量,不是排序
coverage 等:次要护栏,可消融
结果锚点:P1 原版 Pi 50.0% → P2 动态版(含 RF-CLM 回退)69.5%(+39 题,McNemar p=0.0)。

① 输入 Agentic Search 的初始 prompt 构建

# selector 每轮看到的上下文(public_prompt) { "protocol": "agentic-adaptive-selector-v1", "change": { # ← 核心 query:这次改动 changed_paths, changed_symbols, dependency_change, mutation_summary # 改动在干什么(自然语言) }, "bad_case_ids": [...], # 父代历史失败(可展开取详情) "eligible_task_ids": [...200], # 可选任务全集 U "selected_task_ids": [...], # 本轮已选(初始为空) "prior_round_summaries": {}, # 上轮 P/C 配对结果(跨轮自适应) "call_history": [...], # 本轮已调过的工具+返回 "remaining_task_budget": 8, "remaining_rounds": 3 }

上下文=这次改动的"证据包"

  • change(CandidateChangeCard):父→子 diff、改了哪些路径/符号、改动摘要 —— 这就是 query 的来源
  • bad_case(BadCaseCard):父代在哪些任务上、以什么失败模式挂过
  • U:冻结候选任务全集(现 200;协议本意 60)
  • + 预算 / 已选 / 调用历史 / 上轮结果
没有"根源 task 输入":起点是一次改动 P→C,不是某个任务。任务是被这次改动"召来"的量尺。
初始 prompt = 改动证据包

决策/收尾工具

谁驱动搜索?全程 LLM。
自己写 query、自己选调哪个工具、调几次、读完再改写、何时停 —— 这正是 "agentic" 的含义。 BM25/cosine 只是工具内部给返回候选排序,不替 LLM 做决定。

③ 输出 提议 → 配对测量 → 三态裁决

# propose_tasks 的输出:带角色和理由的任务集(不是分数) [ { instance_id: "django-11099", retrieval_role: "repair_cause", evidence_reference: "round-0-call-1", # 必须指向检索过的结果,不能凭空提 expected_signal: "child 应修复此压缩丢约束失败", rationale: "..." }, { instance_id: "sphinx-8475", retrieval_role: "regression", ... } ]
LLM 直接选
propose_tasks 给出任务集。够用就全保留(贪心只在超预算砍/欠预算补时才动)。
→
配对执行(量尺)
P 和 C 各在这批任务上跑:
δ = Y(C) − Y(P) 逐任务。量尺=测量,不排序。
→
确定性裁决
bootstrap + McNemar →
ACCEPT / ROLLBACK / ESCALATE。LLM 不参与。
输出不含标量分、不做裁决;LLM 只负责"检索 + 提议"。+ 一组 LLM 看不到的独立 audit 任务混入量尺防盲区。 Coverage/Redundancy 在量尺冻结后只算一次写报告,不进任何决策,是可消融的次要护栏。

边界 进化范围 · 诚实声明

现在进化的是什么?

  • 实际能跑:策略 / prompt 层(唯一可变面 = strategy.md)
  • 设计目标:整个 harness(源码 + tools + prompts + 依赖)
  • 卡在哪:进化 tool/源码需把 child 关进容器隔离,否则进化代码会在宿主 Pi 进程执行 —— 这道门还没建
  • P2 那次 69.5% 进化的也不是 tool,是 RF-CLM 反馈辅助修复

主动声明的边界(讲出来加分)

  • P2 的 69.5% 用了一轮隐藏官方评测反馈,是"恢复上界",非标准单提交分数
  • 不能据此宣称打赢 DGM / 原版 Pi;P1=50.0% 才是严格可比基线
  • 动态采样 60/140 隔离、A3 多代回退仍是待实现门
  • 数据:summary.json · AGENTIC_...DESIGN.md · 代码 rollback_mvp/adaptive_eval/
一句话总括:动态采样本质就是「以一次改动的 diff + 历史失败为 query 的 agentic 检索」, 产出一批任务当配对量尺,再用确定性统计裁决保留还是回退。coverage/audit 是护栏,不是主干。
